USB CDC Stream and Packetization
=================================

The USB CDC Stream and Packetization subsystem governs the serialization of measurement frames into structured binary packets and handles high-rate data transport over the USB Communication Device Class (CDC) interface to the Host PC.

.. _uuid-cdc0b26e-0acb-4bfe-98db-3505d51942ba:

Subsystem Role & Boundary
-------------------------

UUID: :ref:`CDC0B26E-0ACB-4BFE-98DB-3505D51942BA <uuid-cdc0b26e-0acb-4bfe-98db-3505d51942ba>`

This subsystem forms the embedded endpoint of the Integration-defined wire contract. It wraps the raw ADC samples collected by DMA into binary packets with complete header metadata and transmits them over a Full-Speed USB virtual serial port. It interleaves diagnostic ASCII text responses without corrupting frame boundaries.

Normative Requirements
----------------------

.. _uuid-80007f60-67aa-4f64-9922-9bf326fd33cb:

**Requirement:** The Embedded USB transport system shall format each measurement frame packet with a 28-byte little-endian header beginning with magic bytes ``b"CCD1"`` (0x31444343), protocol version 2, and packet type 1 before transmitting the packet over USB CDC.

   **Rationale:** Standardized magic bytes and protocol version fields allow the Host PC to synchronize incoming byte streams, validate payload boundaries, and reject unaligned data or legacy protocol frames.

.. _uuid-194d547e-2f1f-4d23-bf4e-f2526126af9f:

**Requirement:** The Embedded USB transport system shall transmit complete 7416-byte binary frame packets at rates up to the nominal hardware cadence of 125 Hz under minimum integration time conditions without exhausting USB endpoint buffers.

   **Rationale:** Sustaining the 125 Hz frame rate guarantees 100% data capture fidelity during live spectroscopic monitoring, meeting the temporal resolution needed for dynamic chemical measurements.

.. _uuid-e232dd13-4771-4353-b59d-3d07255ff15a:

**Requirement:** The Embedded USB transport system shall apply a non-blocking transmission timeout of at most 20 ms (``CCD_FRAME_TX_TIMEOUT_MS``) when transmitting packets over USB CDC under host backpressure to prevent permanent execution lockups.

   **Rationale:** If the host application halts or the USB cable is disconnected, blocking indefinitely inside the USB driver would freeze the microcontroller and prevent watchdog servicing and fault reporting.

Binary Packet Layout
--------------------

Each measurement frame packet consists of a 28-byte header followed by 7388 bytes of payload data (total length = 7416 bytes):

.. list-table:: 28-Byte Binary Frame Header Structure (``<4sBBHHHHIIII``)
   :header-rows: 1

   * - Offset (Bytes)
     - Field
     - Format
     - Size (Bytes)
     - Description / Value
   * - ``0``
     - ``magic``
     - ``4s`` (ASCII)
     - 4
     - Magic identifier: ``b"CCD1"`` (``0x31444343``).
   * - ``4``
     - ``version``
     - ``uint8``
     - 1
     - Wire protocol version (must be ``2``).
   * - ``5``
     - ``packet_type``
     - ``uint8``
     - 1
     - Packet type identifier (``1`` = Measurement Frame).
   * - ``6``
     - ``total_samples``
     - ``uint16``
     - 2
     - Total line sample count (``3694``).
   * - ``8``
     - ``effective_start``
     - ``uint16``
     - 2
     - Offset index of first effective pixel (``32``).
   * - ``10``
     - ``effective_count``
     - ``uint16``
     - 2
     - Number of effective optical pixels (``3648``).
   * - ``12``
     - ``flags``
     - ``uint16``
     - 2
     - Status and diagnostic bitmask flags.
   * - ``14``
     - ``payload_bytes``
     - ``uint32``
     - 4
     - Exact payload byte length (``7388`` = ``3694 * 2``).
   * - ``18``
     - ``integration_us``
     - ``uint32``
     - 4
     - Active integration duration in microseconds.
   * - ``22``
     - ``frame_id``
     - ``uint32``
     - 4
     - Monotonically increasing hardware frame counter.

The payload immediately follows the header and consists of 3694 contiguous little-endian unsigned 16-bit integers (``uint16_t``) representing the digitized pixel voltages.

Bandwidth Budget and Wire Pacing
--------------------------------

At the maximum capture rate of 125 Hz (short exposure regime):

.. math::

   \text{Throughput} = 125\,\text{frames/s} \times 7416\,\text{bytes/frame} = 927{,}000\,\text{bytes/s} \approx 7.416\,\text{Mbps}

1. **USB Capacity:** USB 2.0 Full-Speed provides a raw wire signaling rate of 12.0 Mbps, with an effective bulk transfer payload capacity of approximately 9.6 Mbps after protocol overhead. The 7.416 Mbps stream utilizes approximately 77% of available bus capacity.
2. **Pacing Margin:** Each 7416-byte packet requires approximately :math:`6.18\,\text{ms}` to clear the wire. With an 8.0 ms frame period, a margin of :math:`1.82\,\text{ms}` remains between frames for host processing and USB SOF tokens.

Stream Multiplexing and Text Isolation
--------------------------------------

The embedded firmware multiplexes ASCII status messages (e.g., responses to ``PING`` or ``SET_INT`` commands) across the same USB CDC virtual COM port:

* ASCII strings are transmitted as discrete, newline-terminated packets during inter-frame intervals.
* The Host PC demultiplexing parser inspects incoming packet prefixes: packets beginning with ``b"CCD1"`` are routed to the binary reconstruction pipeline, while non-matching packets are directed to the ASCII console logger.
