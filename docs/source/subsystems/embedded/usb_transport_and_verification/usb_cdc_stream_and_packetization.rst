USB CDC Stream and Packetization
=================================

The USB CDC Stream and Packetization subsystem governs the serialization of measurement frames into structured binary packets and handles high-rate data transport over the USB Communication Device Class (CDC) interface to the Host PC.

.. _uuid-cdc0b26e-0acb-4bfe-98db-3505d51942ba:

Subsystem Role & Boundary
-------------------------

UUID: :ref:`CDC0B26E-0ACB-4BFE-98DB-3505D51942BA <uuid-cdc0b26e-0acb-4bfe-98db-3505d51942ba>`

This subsystem forms the embedded endpoint of the Integration-defined wire contract. It wraps the raw ADC samples collected by DMA into binary packets with complete header metadata and transmits them over a Full-Speed USB virtual serial port. It interleaves diagnostic ASCII text responses without corrupting frame boundaries.

Normative Requirements
----------------------

.. _uuid-80007f60-67aa-4f64-9922-9bf326fd33cb:

**Requirement:** The Embedded USB transport system shall format each measurement frame packet with a 32-byte little-endian header beginning with magic bytes ``b"CCD1"`` (0x31444343), protocol version 3, and packet type 1 before transmitting the packet over USB CDC.

   **Rationale:** Standardized magic bytes and protocol version fields allow the Host PC to synchronize incoming byte streams, validate payload boundaries, and reject unaligned data or legacy protocol frames.

.. _uuid-194d547e-2f1f-4d23-bf4e-f2526126af9f:

**Requirement:** The Embedded USB transport system shall transmit complete 7424-byte binary frame packets at rates up to the nominal hardware cadence of 125 Hz under minimum integration time conditions without exhausting USB endpoint buffers.

   **Rationale:** Sustaining the 125 Hz frame rate guarantees 100% data capture fidelity during live spectroscopic monitoring, meeting the temporal resolution needed for dynamic chemical measurements.

.. _uuid-e232dd13-4771-4353-b59d-3d07255ff15a:

**Requirement:** The Embedded USB transport system shall apply a non-blocking transmission timeout of at most 20 ms (``CCD_FRAME_TX_TIMEOUT_MS``) when transmitting packets over USB CDC under host backpressure to prevent permanent execution lockups.

   **Rationale:** If the host application halts or the USB cable is disconnected, blocking indefinitely inside the USB driver would freeze the microcontroller and prevent watchdog servicing and fault reporting.

Binary Packet Layout
--------------------

**Requirement:** The Embedded USB transport system shall serialize each
production frame as the following 32-byte little-endian header, 3694 unsigned
16-bit samples, and a 4-byte CRC32 footer to preserve geometry, timing identity,
and corruption detection across arbitrary USB read boundaries.

**Rationale:** Sample counts alone cannot detect corruption or distinguish
calibrations acquired with the previous ICG waveform.

.. list-table:: CCD1 version 3 (``<4sBBHIHHHHIII``)
   :header-rows: 1

   * - Byte offset
     - Type / field
     - Value or meaning
   * - 0
     - 4 bytes / magic
     - ``CCD1``
   * - 4
     - uint8 / version
     - 3
   * - 5
     - uint8 / packet_type
     - 1
   * - 6
     - uint16 / reserved
     - 0
   * - 8
     - uint32 / frame_id
     - Physical ICG readout counter; gaps identify skipped frames
   * - 12
     - uint16 / sample_count
     - 3694
   * - 14
     - uint16 / effective_start
     - 32 (nominal mapping)
   * - 16
     - uint16 / effective_count
     - 3648
   * - 18
     - uint16 / flags
     - bit 0 ICG synchronized; bit 1 timing fault; bit 2 USB timeout
   * - 20
     - uint32 / payload_bytes
     - 7388
   * - 24
     - uint32 / integration_us
     - Exposure setting active for this frame
   * - 28
     - uint32 / timing_profile_id
     - ``0x00010001``: corrected ICG and 500 kS/s production sampling
   * - 32
     - 3694 uint16 / raw ADC
     - Acquisition order, values 0 through 4095
   * - 7420
     - uint32 / crc32
     - IEEE CRC32 over bytes 0 through 7419, reflected polynomial
       ``0xEDB88320``, initial and final XOR ``0xFFFFFFFF``

**Requirement:** The Host PC frame decoder shall reject version-3 frames with
invalid CRC, geometry bounds, exposure metadata, or ADC range before processing
to prevent corrupted samples from entering calibration and recording.

**Rationale:** A plausible-looking trace can otherwise hide damaged sample data.

**Requirement:** The Host PC frame decoder shall retain support for version-1
and version-2 frames with unknown timing-profile identity to preserve access
to legacy streams without claiming profile compatibility.

**Rationale:** Older firmware does not transmit the information needed to
identify corrected timing or verify the new CRC footer.

Bandwidth Budget and Wire Pacing
--------------------------------

At the maximum capture rate of 125 Hz (short exposure regime):

.. math::

   \text{Throughput} = 125\,\text{frames/s} \times 7424\,\text{bytes/frame} = 928{,}000\,\text{bytes/s} \approx 7.424\,\text{Mbps}

1. **USB Capacity:** USB 2.0 Full-Speed provides a raw wire signaling rate of 12.0 Mbps, with an effective bulk transfer payload capacity of approximately 9.6 Mbps after protocol overhead. The 7.424 Mbps stream utilizes approximately 77% of available bus capacity.
2. **Pacing Margin:** Each 7424-byte packet requires approximately :math:`6.18\,\text{ms}` to clear the wire. With an 8.0 ms frame period, a margin of :math:`1.82\,\text{ms}` remains between frames for host processing and USB SOF tokens.

Stream Multiplexing and Text Isolation
--------------------------------------

The embedded firmware multiplexes ASCII status messages (e.g., responses to ``INTEG <us>`` commands) across the same USB CDC virtual COM port:

* ASCII strings are transmitted as discrete, newline-terminated packets during inter-frame intervals.
* The Host PC demultiplexing parser inspects incoming packet prefixes: packets beginning with ``b"CCD1"`` are routed to the binary reconstruction pipeline, while non-matching packets are directed to the ASCII console logger.
